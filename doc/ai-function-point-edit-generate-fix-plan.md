# 功能点提取与任务通知最终修复方案

日期：2026-11-18

## 已确认的产品决策

- 取消功能点的人工确认/审核门槛。提取成功并保存有效清单后，用户可以直接生成测试用例，无需进入任何测试项执行确认。
- 保留按测试项查看、编辑、新增、删除、剔除/恢复及显式保存。保存成功后，生成使用保存后的内容。
- 有未保存修改时点击生成，明确提示“保存并生成”或取消；保存失败不得提交生成。重新提取覆盖人工修改前须明确提示。
- 不将“取消确认”实现为后台自动全确认。后端生成就绪条件依赖有效功能点、素材一致性和清单版本，不再依赖人工确认状态；历史已确认/待确认数据均兼容，不要求数据库批量迁移。
- 至少一个有效功能点才可生成；未提取、清单为空、全剔除、素材过期须给出具体原因。保持既有生成范围、增量/覆盖及待处理集语义，不新增静默跳过或部分生成。
- 保存和生成保留权限、归属、完整快照/版本、素材指纹以及生成写回的一致性保护。取消确认不会允许旧编辑覆盖新提取，或将旧清单的生成结果认作新清单的结果。
- 用户文档集（8）和性能效率（9）的专用流程保持既有业务语义。
- 完成任务“知道了”或关闭后，同用户、同项目、同 taskId 不再因切页或刷新弹出；新任务正常提醒。运行中收起不表示已知晓终态，完成后仍提醒。
- 任务卡显示项目名称与真实任务范围，避免“项目+长ID”；提取任务不显示用例版本。提供原任务范围的查看入口仅在现有路由能够可靠定位时实施。

## 会话分步与职责

本聊天负责方案、调度和独立代码审核。实现通过从本聊天创建的会话分支执行；顺序运行，共用工作区，不创建额外 Git 工作树，不擅自提交/推送/部署。保护所有已有修改。

### 第一步：取消确认门槛并贯通编辑保存与生成

范围：前端功能点面板、生成入口/共享 hook、相关类型与文案；后端功能点保存、生成前校验和写回保护；必要的契约/回归测试。

验收：

1. 新提取的正常功能点清单不进行任何确认即可提交详细版和常规版生成；顶部范围生成及单项重新生成行为一致。
2. 编辑后显式保存生效；未保存时生成有明确的保存并生成/取消交互，失败和取消均不提交生成。
3. 旧 status=0/1 数据均按有效内容与素材检查；无清单、空内容、全剔除、素材过期仍拦截并说明原因。
4. 异步切测试项、并发编辑/提取、保存重复点击、生成在途清单变更不会串项、漏存或写回过期结果。
5. 用户文档集和性能效率专用流程不被普通功能点门槛影响；增量生成既有成功项不追溯。
6. 用户可见的“待确认、全部确认、确认后生成”等旧流程文案全部清理，历史交付文档明确标注被本方案替代的口径。

第一步完成后由本聊天审查差异及验证证据，发现问题返回原分支整改，再进入第二步。

### 第二步：通知去重与任务卡展示

范围：ai-task-store、全局任务卡、任务展示元信息和必要的类型/API适配。

验收：

1. 信息安全性提取完成→知道了→兼容性→可靠性→刷新，同一个终态任务不再弹出；右上角关闭语义一致。
2. 运行中收起后可继续后台任务，完成仍提醒；同项目新 taskId、不同项目任务均正确处理。
3. 已知晓记录按用户隔离，关闭后慢响应不重新打开，失败/停止/失联/重试/cleanupPending 仍可正确处理。
4. 恢复任务展示所属项目名称及原始特性/子系统名称，不能用当前路由改写任务归属；长名称可查看完整内容，提取卡无无关版本。
5. 无稳定 taskId 的兼容行为明确，不能把所有无ID任务永久去重；刷新恢复不丢后台任务能力。
